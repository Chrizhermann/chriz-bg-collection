# Cross-platform desktop GUI stacks, August 2026 — evaluated for: wizard UI + background downloads + subprocess orchestration with live console streaming + multi-GB file operations, Windows-first, OSS hobby project

## Cross-cutting: code signing & notarization (applies to all four)

**Signing assumption superseded, 2026-09-07:** the historical recommendation below
predates CEBG's linked UnRAR dependency. Source publication does not establish
SignPath eligibility; its OSI-license requirement conflicts with the current UnRAR
terms. No sponsorship has been granted. Use the [current signing review](../../audits/2026-09-07-signing-dependency-review.md)
for requirements and alternatives; historical prices/eligibility below are not a current offer.

- **Windows**: Unsigned EXEs hit the SmartScreen "unrecognized app" wall; per-file-hash reputation resets every release, which is fatal for an auto-updating hobby installer. Two realistic 2026 paths:
  - **Azure Trusted/Artifact Signing** — GA as of early 2026: $9.99/mo Basic (5,000 sigs), certs issued from Microsoft's own CA and renewed daily, builds SmartScreen reputation fast. Eligibility now: US/Canada/EU/UK **businesses incl. self-employed** (individual-developer signup still US/Canada only) — relevant for a German self-employed consultant: the business route should work ([devclass](https://www.devclass.com/security/2026/01/14/code-signing-windows-apps-may-be-easier-and-more-secure-with-new-azure-artifact-service/4079554), [Rick Strahl setup war story](https://weblog.west-wind.com/posts/2025/Jul/20/Fighting-through-Setting-up-Microsoft-Trusted-Signing), [melatonin.dev guide](https://melatonin.dev/blog/code-signing-on-windows-with-azure-trusted-signing/)).
  - **SignPath Foundation** — free code-signing for qualifying OSS projects (Sectigo-issued; identity verified against the repo, not you personally; CI-integrated). Best-fit for a hobby OSS installer ([overview](https://comparecheapssl.com/free-code-signing-certificate-and-how-to-get-it/)).
- **macOS (later)**: identical cost for every framework — Apple Developer Program $99/yr, `notarytool`, notarization mandatory outside the App Store since Catalina; staple the ticket for offline Gatekeeper ([Apple](https://developer.apple.com/news/?id=04102019a), [guide](https://www.swiftyn.com/learn/macos/macos-notarization-guide-gatekeeper)). Framework tooling differences: Tauri and electron-builder/@electron/notarize automate it in the build; Avalonia/egui you script it yourself.
- Signing is therefore **not a differentiator between stacks** — it's a fixed project cost. Pick SignPath (free) now; Trusted Signing later if SignPath declines.

## 1. Tauri 2.x (Rust core + web UI)

- **Maturity/maintenance**: 2.0 stable Oct 2024; core at **2.11.5 (July 2026)**, steady patch cadence; plugins actively maintained (updater got NSIS+MSI+Deb+RPM+AppImage coverage and fixes into Feb 2026) ([releases](https://tauri.app/release/core/), [updater changelog](https://tauri.app/release/updater/all-versions/)). Mobile support added in v2 — it's no longer a small experiment.
- **Bundle size**: best in class — ~96% smaller than equivalent Electron; single-digit MB installers on Windows because it uses the OS webview (WebView2, preinstalled on Win10/11 — **Windows-first is Tauri's best-case platform**) ([comparison](https://tech-insider.org/tauri-vs-electron-2026/), [PkgPulse](https://www.pkgpulse.com/guides/electron-vs-tauri-2026)).
- **Auto-update**: first-party `tauri-plugin-updater`; artifacts minisign-signed (Ed25519, mandatory — cannot ship unsigned updates), works off a static `latest.json` on GitHub Releases, supports NSIS/MSI on Windows ([docs](https://v2.tauri.app/plugin/updater/), [walkthrough](https://ratulmaharaj.com/posts/tauri-automatic-updates/)).
- **Subprocess + streaming**: strong. Two options: shell plugin `ShellExt` → `spawn()` → async channel of `CommandEvent::Stdout/Stderr/Terminated`, plus sidecar bundling for shipped binaries ([shell plugin](https://v2.tauri.app/plugin/shell/), [sidecar](https://v2.tauri.app/develop/sidecar/), [streaming discussion](https://github.com/tauri-apps/tauri/discussions/8641)); or — better for this workload — plain `tokio::process` in the Rust core with events emitted to the UI. Full control over encoding/interactive-prompt handling of `weidu.exe` output, no IPC per-line overhead concerns if you batch.
- **Download/filesystem**: do it all in Rust (`reqwest` streaming + `tokio::fs`) — progress events to the UI, bytes never cross the IPC boundary. Multi-GB directory copies are native-speed Rust. Plugins (fs/http/upload) exist for frontend-driven cases but aren't needed here.
- **Contributor approachability**: split — the wizard/log UI is plain web tech (largest contributor pool of any option), but the core logic (process orchestration, copying, manifest handling) is Rust, a higher bar. Two-language project with an IPC seam to document.
- **Caveat for the later Linux port**: webkitgtk is the known weak leg — rendering glitches, font-weight bugs, `WEBKIT_DISABLE_DMABUF_RENDERER` workarounds ([issue](https://github.com/tauri-apps/tauri/issues/13157), [debug docs](https://v2.tauri.app/develop/debug/linux-graphics/), [fonts](https://medium.com/@dasunnimantha777/fonts-render-too-bold-in-rust-tauri-wails-on-linux-a-webkitgtk-bug-and-how-to-fix-it-8b6a0b27b613)). Tolerable for a utility app; know it's there.

## 2. Electron (current stable, no formal LTS)

- **Maturity/maintenance**: most mature option, but **no LTS exists** — 8-week major cadence tracking Chromium; only the latest 3 majors supported (41.2.1 stable as of Apr 2026, 42 in beta) — you're on a permanent upgrade treadmill for security fixes ([timelines](https://www.electronjs.org/docs/latest/tutorial/electron-timelines), [endoflife.date](https://endoflife.date/electron)).
- **Bundle size**: worst — ~120MB of Chromium+Node per OS before your code; production installers 80–200MB, ~300–500MB RAM at runtime; universal macOS builds ~250–300MB ([2026 guide](https://www.forasoft.com/blog/article/electron-desktop-app-development-guide-for-business), [PkgPulse](https://www.pkgpulse.com/guides/electron-vs-tauri-2026)). For a tool whose job is to *save* users disk churn, this is a bad look.
- **Auto-update**: best in class. `electron-updater` (electron-builder): GitHub Releases/S3, differential updates, staged rollouts, ~2 lines of code; plus **free hosted update.electronjs.org for OSS apps** ([electron-builder](https://www.electron.build/auto-update), [Electron docs](https://www.electronjs.org/docs/latest/tutorial/updates)).
- **Subprocess + streaming**: excellent and boring — Node `child_process.spawn` with stdout/stderr streams piped straight into the renderer; decades of Stack Overflow coverage.
- **Download/filesystem**: Node streams + `fs` — fine for multi-GB copies; everything in one language.
- **Contributor approachability**: highest — TypeScript end-to-end, zero exotic toolchain. If maximizing drive-by contributions is the top priority, Electron wins that single axis.

## 3. Avalonia 11+/12 (C#/.NET)

- **Maturity/maintenance**: strong upward trajectory — **Avalonia 12.0 shipped Apr 10, 2026** (major rendering-pipeline rework, up to 18× FPS on complex layouts; WebView component open-sourced); team doubled to 19 people on a 3-year Devolutions sponsorship ([Avalonia 12 blog](https://avaloniaui.net/blog/avalonia-12/)). v12 requires .NET 8+, recommends .NET 10; dropped .NET Framework/Standard; compiled bindings on by default ([breaking changes](https://docs.avaloniaui.net/docs/avalonia12-breaking-changes)). Skia rendering = pixel-identical UI on all three OSes (no webview variance — the Linux story is *better* than Tauri's).
- **Bundle size**: middle — self-contained ~60–80MB, real trimmed apps ~26MB reported, NativeAOT smaller/faster still ([discussion](https://github.com/AvaloniaUI/Avalonia/discussions/9217), [NativeAOT docs](https://docs.avaloniaui.net/docs/deployment/native-aot)).
- **Auto-update**: no first-party, but **Velopack** (Squirrel's successor) is excellent: one command produces installer + delta updates + portable package for Win/macOS/Linux, GitHub Releases hosting, ~10 lines of app code ([velopack.io](https://velopack.io/), [GitHub](https://github.com/velopack/velopack)). NetSparkleUpdater has an Avalonia UI package as an alternative.
- **Subprocess + streaming**: excellent — `System.Diagnostics.Process` with async stdout/stderr reading is a first-class, well-documented .NET API; marshal lines onto the UI thread and done. No IPC seam at all.
- **Download/filesystem**: `HttpClient` streaming with progress + `System.IO` — top-tier for multi-GB operations, robust cancellation via `CancellationToken`.
- **Contributor approachability**: good-with-an-asterisk — C# is mainstream, and notably **the existing BG modding tool ecosystem skews C#/.NET** (Project Infinity, the current WeiDU mod manager, is C#), so *domain* contributors likely already know it. XAML/MVVM has a learning curve for web people; fewer casual UI contributors than an HTML frontend.

## 4. Lightweight native: Rust egui (and iced / Flutter briefly)

- **egui/eframe**: most-downloaded Rust GUI (~10× iced) but still **0.x with API breaks every release** — 0.33 (Oct 2025) → 0.34 (Mar 2026, renamed the core `App::update` method) → 0.35 (Jun 2026) ([eframe releases](https://docs.rs/crate/eframe/latest), [2026 landscape](https://wrenlearnsrust.com/posts/2026-03-11-rust-gui-landscape-2026.html), [rust-windows-gui guide](https://rust-pc.github.io/rust-windows-gui.html)). Single ~5–15MB exe; immediate-mode makes a live-scrolling log console trivially easy (repaint on every line); subprocess = `std::process`/`tokio` + channels — fine but all hand-rolled. No updater story of its own (Velopack does have Rust bindings). Downsides for a wizard app: "debug-UI that grew up" aesthetics, weak accessibility/i18n, every polish item is manual.
- **iced 0.14** (Dec 2025): big release (reactive rendering, headless testing), used by COSMIC, explicitly the **last experimental release before 1.0** — promising but still pre-1.0 churn and thin docs ([release](https://github.com/iced-rs/iced/releases/tag/0.14.0), [Phoronix](https://www.phoronix.com/news/Iced-0.14-Rust-GUI-LIbrary)).
- **Flutter desktop**: genuinely matured — **Canonical took over desktop maintenance/roadmap in May 2026**, multi-window support landed ([omgubuntu](https://www.omgubuntu.co.uk/2026/05/flutter-desktop-canonical-maintained), [state of Flutter](https://devnewsletter.com/p/state-of-flutter-2026/)); `Process.start` streaming is fine. But desktop auto-update relies on the third-party `auto_updater` wrapping Sparkle/WinSparkle ([pub.dev](https://pub.dev/packages/auto_updater)), Windows is behind macOS in production-quality packages, and Dart is the smallest contributor pool for this niche. Not a fit here.

|---|---|---|---|---|

| Linux later | webkitgtk warts | Fine, heavy | Fine (Skia, consistent) | Fine |

## Ranked recommendation for this workload

1. **Tauri 2.x** — best overall fit. Windows-first plays to its strongest platform (WebView2 preinstalled); a mod-installer utility *should* be a small trustworthy download, and 5MB vs 150MB matters for that; the Rust core is ideal for exactly the hard parts of this app (spawning WeiDU installers, streaming/parsing their output, multi-GB copies with progress, resumable downloads), and the built-in cryptographically-signed updater over GitHub Releases is zero-infrastructure. HTML is also the best medium for a wizard plus a virtualized live console. Accept: two-language architecture, Rust bar for core contributions, webkitgtk quirks when Linux arrives.
2. **Avalonia 12 + Velopack** — very close second, and **flips to #1 if you weight single-language simplicity or expect contributors from the BG modding scene**, which is historically C#/.NET (Project Infinity is C#). Superb `Process`/`System.IO`/`HttpClient` ergonomics with no IPC seam, consistent Skia rendering on all OSes (cleaner Linux story than Tauri), well-funded project. Costs: ~40–80MB artifacts, XAML learning curve, updater is third-party (though Velopack is excellent).
3. **Electron** — everything works with the least friction and the biggest contributor funnel, and its update story is unmatched — but 150MB+/300–500MB RAM and a Chromium security treadmill is heavy machinery for an installer orchestrator. Choose only if TS-only contributions dominate all other concerns.
4. **egui (or iced/Flutter)** — viable for a minimal personal tool (tiny exe, trivially easy log streaming), but wizard polish, accessibility, updater, and every UI nicety are hand-rolled, egui's API churns each release, iced is pre-1.0, and Flutter's desktop update story plus Dart's niche pool rule it out for a contributor-friendly OSS installer.
